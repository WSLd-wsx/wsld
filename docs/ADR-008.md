# ADR 008: Post-shutdown interactive stall remains unresolved

Status: real restart initially worked, then became unresponsive; diagnosis in progress.

Diagnosis update: [ADR 010](ADR-010.md) records the diagnostic retest's quota
failure before VM loss and a concrete migration omission: Core failed to select
the reference's verified 64/32-page CPU-cache profile. That wiring is corrected;
new interaction acceptance remains separate. Earlier unknown-order statements
below describe the first lifetime, whose logs still lack call timestamps.

Follow-up: [ADR 009](ADR-009.md) records the user-authorized termination of the
retained Host and the criteria for admitting a fresh desktop.

The successful bounded shutdown in ADR 007 does not establish interactive stability
of the next desktop. On 2026-11-05 the compiled public CLI returned 0, recorded a
new first frame, and a live query observed the exact Guest session active/running.
The user confirms initial interaction and manually starting the screensaver.
Later, the renderer and WSL-hosted command execution became unresponsive. The user
reports two such occurrences and recovered by stopping WSLService and restarting
WSL. The agent did not perform that service recovery. The exact point at which
the screensaver stopped animating is unknown; the green screenshot is not evidence
of graphics corruption or a known screensaver-specific trigger.

## Verification

The recorded session became unresponsive after startup. Startup and first-frame
evidence establish neither sustained interaction nor normal resource retirement.
Use the public desktop status command to inspect the current session.
