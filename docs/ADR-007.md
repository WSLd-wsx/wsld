# ADR 007: Fresh admission after original VM and independent Host exit

Policy update: [ADR 009](ADR-009.md) supersedes the historical exit-log gate below.
Current HCS/Host observations and fresh Guest checks authorize a new VM lifetime;
no operator recovery receipt or edited failure state is required.

Status: fresh admission, real Omarchy startup and whole-WSL shutdown retirement
passed without restarting Windows. See the separately recorded acceptance below.

Follow-up: the next desktop initially worked but later became unresponsive along
with WSL-hosted commands. Interactive restart stability failed; the user recovered
through WSLService. See [ADR 008](ADR-008.md). The bounded shutdown observations
below do not establish that the subsequent desktop remains healthy.

The current architecture owns graphics in an independent Native Host and has no
custom WSLService plugin. Windows restart is not a universal prerequisite for a
new desktop lifetime. Keep Windows-reboot recovery, but also admit a new lifetime
when all of these independent observations are established:

- The previous log contains the exact instance's original-HCS-handle VM exit marker.
- The previous Native process identity has ended; no known Native/input/Venus/
  Rutabaga graphics Owner process remains. Observation failures cannot mean absence.
- HCS enumeration succeeds, excludes the old VM, and identifies exactly one
  different, nonzero current WSL VM GUID. Recheck that GUID at fresh startup.
- Fresh Guest preflight succeeds: no loaded reference modules, retained descriptors,
  seat owner or incompatible component/kernel state. No prior module or device is
  reused, recycled or unloaded via this recovery route.

The old lifecycle remains failed, with `native_retirement_confirmed=false`.
Record `recovered_after_vm_and_host_exit=true` separately from
`recovered_after_windows_restart`. A new successful lifetime does not certify the
old application's graceful GPU drain. This is fresh admission under process/VM
isolation, not arbitrary repair of retained backing. Keep the old diagnostics and
archive its ownership pointer in the successor. Do not kill a process, remove a
module or change the old record merely to satisfy this decision.

Microsoft documents that process exit closes that process's handles, while shared
objects may survive other references ([process termination](https://learn.microsoft.com/en-us/windows/desktop/ProcThread/terminating-a-process)).
HCS compute systems are ephemeral after exit ([HCS overview](https://learn.microsoft.com/virtualization/api/hcs/overview)).
These contracts motivate a generation boundary, not a claim that PID disappearance
alone proves all GPU work completed. Thus require original VM exit, no graphics
owners, and fresh Guest admission; retain normal-retirement checks unchanged.
