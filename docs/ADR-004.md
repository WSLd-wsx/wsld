# ADR 004: Renderer close requests normal retirement

> Historical experiment paths referenced below were moved to the prototype repository; see [Experiment migration](EXPERIMENT-MIGRATION.md).

Status: implemented; real r11 WM_CLOSE acceptance passed on 2026-11-05.

## Decision

The Native graphics Owner retains queue service during retirement. The renderer
window must request that Owner's existing exact-instance stop coordinator before
destroying output. Core remains a short-lived command caller; no watchdog daemon,
GPU-brand branch, service plugin or private GUI dependency is added.

Direct bootstrap publishes its already-created stop event through the Windows
environment before renderer initialization. The paired renderer reads that value
through the Windows API, validates the canonical GUID name and opens the event.
The existing WM_CLOSE branch signals it without cancelling presentation or hiding
the output window. Guest retirement, GPU/context drain, memory unmapping and
device/bootstrap closure keep their verified order. Native now waits up to ten
seconds for the input companion's natural exit; failure preserves quarantine
instead of terminating that process to manufacture success.

Missing/malformed/unowned stop events reject window creation. Core requires the
new complete 12-file bundle for startup, and retains observation of the exact
legacy Native binary. Neither old DLL fallback nor mixed-pair admission is allowed.
Runtime cache configuration is not a persisted running-state authority. Same-user
replacement races/default event security and unsigned components remain limits.

## Narrow recovery after an already completed Windows reboot

An old lifetime can be superseded only if Windows boot FILETIME is later than
its recorded process creation, the exact old Host is absent, HCS observation
succeeds and the old VM is absent. Fresh Guest preflight must also reject any
remaining device, module owner or session. The old record is preserved with
`recovered_after_windows_restart=true` and `native_retirement_confirmed=false`.
The current Core embeds and hashes its observation adapter rather than executing
an older adapter from the retained lifetime directory.

This permits the user's already rebooted environment to start a clean test. It
does not restart Windows, bypass current-owner checks, certify the old GPU drain,
or implement recovery from `wsl --terminate`/`wsl --shutdown` within the same boot.

fresh Iris Xe acceptance and second-start acceptance for this pair remain separate.

Formal graphics source/package publication remains with the component owner;
reference checkouts were not modified. No licenses, remote refs or releases changed.
