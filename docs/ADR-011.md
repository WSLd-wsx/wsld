# ADR 011: Fit the desktop to its Windows monitor

Status: implemented, bounded live verification on 2026-11-05.

Core measures the corresponding admitted Native Host window on its current
monitor. A small Win32 adapter enters per-monitor-v2 awareness temporarily,
reads the monitor work area (which excludes the Windows taskbar), and uses the
window's actual styles and DPI with AdjustWindowRectExForDpi to subtract the
caption and borders. Coordinates, client dimensions and image dimensions are
physical pixels. Do not divide available pixels by DPI a second time.

Core chooses the largest-area common resolution advertised by the live Guest
output that fits these bounds; ties prefer width and then refresh rate. The
current policy accepts advertised refresh rates from 55 through 61 Hz. It does
not invent a modeline or select a GPU-specific branch. No fitting mode is an
explicit error. Windows DPI / 96 supplies the intended Guest scale. The pinned
Hyprland compositor requires integral logical extents; select the closest clean
scale in its 1/120 increments, and report both requested and applied scale.

Reuse the verified renderer's WSX_WINDOW_FIT_CLIENT message (WM_APP + 2), its
per-monitor-v2 window thread and source-mode fitting. No renderer, GPU protocol,
Native profile or device owner change is needed. The existing 64-page reclaim
watermark / 32-page target remains intact. Position the outer window centrally
within the selected work area and read back actual dimensions and bounds.

The Guest adapter uses the root-owned runtime descriptor, non-root account,
WSX_DESKTOP_INSTANCE, DRM node, pinned compositor path and live Hyprland socket
identity to address the current session. It uses the pinned compositor's existing
hl.monitor runtime control, then verifies mode and scale. It does not alter user
configuration, environment files or the rootfs image. This adapter currently
supports the admitted single-output, unrotated Lua Hyprland session. An upstream
Guest display ABI extension can replace the adapter when rootfs publishes one;
unknown compositors must fail explicitly.

All startup paths call the same Core fitting operation after the first frame.
`wsld.exe -d DISTRO_NAME desktop fit` applies it again to an existing bound
session, for example after moving the window to a different monitor. The command
resolves current WSL/Guest/Host identity rather than an active-lifetime pointer.
A registration lock serializes cooperating desktop commands. It also revalidates
process creation identity and both endpoints. An external stop or monitor/DPI
change can race fitting; report failure and keep diagnostics, without stopping
the Host or claiming rollback. A startup fitting failure reports that the desktop
already started and may be retried with `desktop fit`.

Limits: this is startup/explicit fitting, not a background display watcher. Moving
the window across monitors, Windows DPI/work-area changes and user config reloads
need another fit command. Minimized/maximized windows must first be restored.
Multi-output Guest layouts, arbitrary rotated output, application-specific X11 or
GTK scale overrides and startup without a first frame are outside this slice.
First-frame bootstrap may briefly show the original small window; this does not
claim flicker-free initial creation. No independent Iris Xe, high-DPI physical
monitor or multi-monitor hardware acceptance is inherited from unit tests.
