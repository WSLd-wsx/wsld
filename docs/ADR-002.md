# ADR 002: explicit candidate graphics lifetime and kernel evidence reuse

Status: accepted for the bounded local candidate workflow, 2026-11-04.

Reuse the exact historical native Host, renderer, input component and six kernel
modules that share Iris/RTX evidence. Select the current active adapter by the
actual Windows display/Vulkan LUID join, not a GPU-vendor branch. Core owns
instance admission, runtime configuration and receipts; rootfs owns the Guest
session. The independent graphics Host remains the GPU Owner and is not a second
business Core or a service. No prototype checkout is a runtime dependency.

Same-major WSL module reuse is the starting point. Check the actual running
kernel by Build ID and compare all imported symbol CRCs against its export tables
and the module package. A full kernel-release spelling change alone does not
request a rebuild. Never force module versions. The current check resolved the
275 previously unobserved imports and admitted the existing six files with all
615 imports matched. This does not repeat historical GPU qualification or claim
that every same-major kernel configuration is compatible.

The experimental entry pins an explicitly supplied reference closure and an
owned r10 import. It does not override stable release compatibility metadata or
invent a minimum Core version. Normal versioned component distribution, source
provenance delivery, signatures and general package upgrade admission remain
unresolved. The product GUI is not yet wired to these candidate controls.

The actual run displayed 1,235 opaque frames and completed user-requested native
retirement. The exact-instance Guest marker, zero retained memory, final native
closure and process exit are separate requirements. A missing window or systemd
unit is insufficient. The legacy Host has an input-child kill fallback after GPU
retirement; this bounded run did not separately establish graceful input exit.
Do not equate process disappearance with successful input cleanup.

Retain failed startup intents and native receipts. Only failures provably before
native creation can use the explicit retry command after their children exit.
Do not unload retained shared modules or automatically rebind another lifetime.
A restart policy needs additional owner-reconfiguration work or specific operator
authorization; this trial does not implement it.

PowerShell process launch retained caller pipes in a real run and in an isolated
sleeping-child fixture (13.056 seconds for a 12-second child). Final source uses
Rust process creation with CREATE_NO_WINDOW, a separate process group and
independent standard handles. DETACHED_PROCESS made the CLR fixture exit early
and was rejected. The final Windows regression observes caller output EOF while
the child is still alive, then waits for its natural exit. This is process-layer
evidence, not a second GPU run. Public PE subsystem and three-copy contract are
unchanged.

Evidence and exact tested/final binary distinction: STATUS.md,
DESKTOP-CANDIDATE.md and artifacts/desktop-integration-20261104/summary.json.

## Restart extension, 2026-11-05

Supersedes the earlier absence of an owner-reconfiguration path. Implement the
reference launcher's narrow normal Owner reload, gated by full previous native
retirement, exact loaded-module build identities, matching old module parameters,
absence of old or foreign device/session owners and kernel refcount checks.
Retain the other five modules. No vendor-specific variant or new kernel protocol
is introduced. The no-module-unload session boundary requires explicit operator
authorization before executing this step; the read-only restart check and
`--reload-retired-owner` flag make the action reviewable.

The successor pointer and recycle intent precede side effects. Interrupted
reconfiguration remains a retained failure and cannot use preflight retry.
The old receipt remains available; deleting a pointer is not retirement.

The 2026-11-05 execution was explicitly authorized and passed. Subsequent debugging
showed that no-console flags alone were insufficient: both graphics and persistent
WSL children now use STARTUPINFOEX with an explicit standard-handle list. WSL
options must retain bare token spelling. Build 04 returned its caller while the
real desktop stayed alive. The loaded-module identity and retirement gates were
not weakened to address process-launch failures. Previous failures are preserved.

Module and device helpers do not use subprocess.run timeout-based termination.
If Core observation times out, the in-flight Windows caller and recycle intent
remain retained; an unknown operation never authorizes another restart. This
final failure-path safeguard is built/tested separately from the successful
build-04 desktop run.
