# ADR 012: Connect the verified CachyOS Plasma desktop

Date: 2026-11-05. Status: implemented; bounded live startup/display/input accepted.
Normal close, external termination and restart on this exact pair remain untested.

## Reuse and ownership

Core admits the owned `wsx-cachyos-plasma-2026.11.4-r1` pre-release by its import
receipt, actual WSL registration/disk and exact archive SHA-256:
`9db257a2353f6ac484808fca3ed4cc12cbf4df5b55239536f55147cb0e080d1f`.
It retains the existing Omarchy adapters and uses the same independent Native
Host, input bridge, DRM access adapter, kernel symbol admission and opaque-v1
transport. No custom WSLService, business daemon, staging or GPU-specific branch
was introduced. The explicit 64/32 Guest RAM reclaim watermark remains mandatory.

The historical reuse basis is `wsx-guest-sources/archived-evidence/
rootfs-cachyos-r2-start-01/result.json` (SHA-256
`0d1f8c7c66cb68793201c65b68e33a2323bd7e41fc220ffea9feeea79def4674`),
`DIRECT-HOST.md`, `ROOTFS-HANDOFF.md` and `start-cachyos-plasma.py` under the
prototype production directory. That trial demonstrated Plasma frames, normal
Guest logout and same-Host session restart on Iris Xe; it did not establish full
Native device retirement or RTX acceptance. The Core DRM access adapter matches
that trial byte for byte. Historical acceptance is not inherited by this image.

The current image packages the rootfs-owned verified Plasma adapter in
`/usr/bin/wsx-guest`. Core invokes that interface instead of copying a second
Plasma startup implementation. Preflight verifies the installed private Mesa
26.1.8, Venus 26.2.4 and KWin 6.8.1 / ABI 2 manifests and actual files. The initial implementation called a Guest Python admission function.
[ADR 013](ADR-013.md) replaces that cross-repository internal call with the
public Guest protocol for new images and an isolated legacy lock check for old
images. Both check installed KWin/Plasma/Qt against the Guest package lock. Host CPU admission independently checks x86-64-v3.
Initialization remains shared, interactive and non-root; credentials are not
included in command arguments, environment, evidence or chat.

## Paired retirement helper

The previous Native helper hard-coded Omarchy PAM/session cleanup. The new
`integration/graphics-lifetime/plasma-retirement.py` selects the exact loaded
Plasma instance unit and invokes the existing Guest `stop --instance` interface.
Guest owns normal Plasma logout and KWin-before-input/seat ordering. The helper
requires the inactive unit, removed seat/owner and no instance-tagged processes
before continuing the existing exact PCI/Native retirement sequence. A failed
logout retains resources; it does not fall back to forced termination. An absent
Plasma unit preserves the existing Omarchy path.

The paired bundle receipt is
`685325f5032f2b60f17a330a25e58c7fd94b1192398174854b3dcefc3a4eb40b`.
CachyOS defaults to `%LocalAppData%\WSX\cache\graphics\reference-685325f5032f`
and rejects older bundles without this helper. Omarchy's default is unchanged.
Native SHA-256: `a38cdb40d2839f417658651bfd7ea638f4b6c2e0d2062be88c46472ed0fff5ee`.
Renderer SHA-256: `0826268b927ab45487bbde06c4e96cee7c76fa1dc7cf706ac11688f1ac1fb28b`.
Renderer sources match the previous verified diagnostic pair; Native GPU/memory
sources are unchanged. Native differences are the Guest retirement helper and
relocated build paths, recorded in the source inventory/comparison. Rebuilt
binary identity is not claimed equal to the prior binary.

## Display and observation

Daily commands continue to use the actual WSL distro name. Status discovers the
live Native identity and queries the exact Plasma systemd unit without using the
installation index or a persisted running-state pointer.

The display adapter binds a unique KWin PID, process start time, instance marker,
DRM node and process-owned Wayland socket. It runs `kscreen-doctor` as the actual
Guest user to query physical modes and apply an advertised mode and scale.
The common Core policy chooses the largest admitted common mode fitting the
Windows work area/frame at current DPI, then verifies both ends after resizing.
The renderer title uses the actual distro name. Only a single unrotated output
is supported. KWin may persist display settings through its own API; Core does
not edit user configuration directly.

KScreen JSON fields and atomic output operations were checked against upstream
[serialization](https://raw.githubusercontent.com/KDE/libkscreen/master/src/configserializer.cpp)
and [doctor implementation](https://raw.githubusercontent.com/KDE/libkscreen/master/src/doctor/doctor.cpp).
The installed runtime was then exercised, rather than relying solely on mocks.
Root-owned component manifests have a 2 MiB bound; session/initialization
descriptors retain the 64 KiB bound and ownership/mode checks.

Evidence: `artifacts/cachyos-desktop-20261105-01`;
public package: `artifacts/cachyos-desktop-build-20261105-04/package`;
graphics build: `artifacts/graphics-cachyos-pair-20261105-01`.

- Native MSVC: all 60 tests pass; all three public PE hashes match.
- Seven Python mock cases pass, covering KScreen mode semantics, replaced
  compositor refusal and retirement ordering/failure. These are simulated checks.
- Real preflight passed without an existing graphics owner, device creation,
  module reload or service/WSL restart. Guest account `wen`, UID 1000 and timezone
  Asia/Shanghai were observed; initialization was not repeated.
- Compiled build 02 launched the actual Plasma desktop and first frame. Its final
  fitting stage failed because the valid 212326-byte KWin manifest exceeded the

- Build 04 `desktop fit` returned 0 on the same live Host. KWin and the Windows
  client both confirmed 1920x1440 at 100% (96 DPI), within work area 2520x1632.
  The corrected title and desktop screenshot are archived. No second Host started.
- Build 04 `desktop status` returned 0; exact Plasma unit was active/running,
  Native identity matched the actual registration and no other Host was observed.
  `native_running_unverified` remains accurate: this Host has no live health RPC.
- The user confirmed normal display, mouse and keyboard. The 11:40 UTC live-log
  prefix records 4672 successful frame presentations and working RAM reclamation;
  this is bounded observation, not indefinite stability or GPU retirement.

No desktop was stopped, module unloaded, Host killed, service restarted or distro
removed for this run. The desktop remains running. Build 04 has not yet undergone
a fresh complete start/close/restart cycle. Whole-VM shutdown, RTX, multi-monitor,
HiDPI Plasma, application coverage and clean-machine deployment remain separate
acceptance. Runtime staging is an explicit verified experimental component step;
production component distribution and fully self-contained graphics source
packaging remain unfinished. The product does not search the prototype at runtime.
