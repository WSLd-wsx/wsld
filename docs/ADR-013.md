# ADR 013: Versioned Guest control instead of image-tag adapters

Date: 2026-11-05. Status: source implementation and focused regression complete;
new-protocol rootfs/device lifecycle acceptance is pending. This supersedes the
cross-repository Guest Python import and image-version admission described in
ADR 012. It does not supersede the recorded historical hardware results.

## Decision and research

The [desktop investigation](DESKTOP-PROTOCOL-RESEARCH.md) covers GNOME, Plasma,
Xfce, Cinnamon, COSMIC and Hyprland, plus architecture probes from Niri/Sway/LXQt/
Budgie. Wayland/X11, display APIs, session ownership, input, DPI and permission
models vary independently. Core chooses policy from verified capabilities; Guest
owns compositor tools, package locks, unit names, sockets and session internals.
Adding another desktop must not add another Windows lifecycle implementation.
Research is required now; installing every desktop is not an Alpha prerequisite.

New images declare their control/lifecycle/display and graphics requirements in
`desktop_compatibility`. The public protocol is specified in wsx-rootfs
`docs/guest-control-protocol.md`; neither checkout is a build/runtime dependency
of the other. `wsx-guest host-call` is one bounded JSON request through WSL, not a
business daemon or a conversion of Core's internal Rust API into RPC.

Core 0.2.1 records the verified release manifest and its canonical JSON digest
inside the immutable import receipt. Future starts bind the actual WSL GUID,
disk, archive and channel to that snapshot, independent of download-cache eviction.
The digest detects changes relative to the receipt; it is not a publisher signature
or protection against a hostile same-user rewrite of both data and digest.
Image versions no longer choose compatible component versions. Declared new
Guest versions can change their implementation while preserving the same public
requirements. Unknown required versions/capabilities fail without legacy fallback.

Old images lacking the declaration use a complete known component-input closure,
held in `core/compatibility/legacy-desktop.json`. Old imports lacking a manifest
snapshot retain narrow exact-archive migration exceptions. They are not a wildcard
for new inputs or adoption of unrelated WSL registrations. Only the existing two
distribution IDs are onboarded in the product catalog; the control contract itself
has no desktop-brand dispatch. Catalog/version policy remains separate work for
each future distribution.

## Implemented boundary

- `compatibility.rs`: verified declaration/import binding and paired runtime choice.
- `guest_protocol.rs`: envelope negotiation and display wire conversion.
- `desktop-control.py`: public preflight for declared images; isolated legacy
  package/manifest adapter for existing images. It no longer imports Guest internals.
- `desktop_*_windows.rs`: shared startup/account/observation/display orchestration.
- Rootfs `guest/protocol*.py`: versioned operations and Guest-owned compositor/
  normal-retirement implementations. Display adaptation reuses the working WSX
  Hyprland/KScreen code; retirement reuses the verified exact-instance helper.
- Native `protocol-retirement.py`: calls public `session.stop` for declared images,
  validates the response identity and retains the existing device/mapping drain.

Display snapshots carry output collections, opaque IDs, physical pixels,
logical coordinates, rational scale, millihertz and session/configuration
versions. The Alpha only implements one unrotated active output and backend-default
persistence. It rejects stale observations and checks actual applied dimensions.
Snapshot validation is not an atomic backend transaction. Normal Guest logout,
unit exit and GPU retirement remain distinct. Input transport is unchanged;
portals/IME/clipboard/relative capture are not newly advertised capabilities.

must have a new admitted pairing; a compatible control version alone is insufficient.

Final Windows/MSVC development package:
`artifacts/compatibility-build-20261105-05/package`. All 68 top-level tests passed
(1 SDK, 56 Core, 5 release, 2 process-store, 4 host). One PE is copied three times;
all SHA-256 values are
`a3c9da895e9b0be800be1835464ee2799d1df6d5352da5b454861b6d9ec2b7bf`.
62 Python tests passed across Guest transport, adapters, staging, schema, release
contract and license boundaries. These are controlled/fixture tests, not new GPU
acceptance. Earlier compilation errors and the updated staging fixture failure
are retained in the evidence directory and do not count as passes.

Read-only compiled build 04 compatibility checks used the existing Windows
registrations. CachyOS returned exit 0: the paired runtime and 1,734 KWin, 59 Mesa
and 2 Venus files were verified against the Guest metadata and package lock.
This check explicitly reports `desktop_acceptance:false`. The requested Omarchy
r11 lookup returned exit 1 because discovery did not find exactly one matching
WSL registration. No reimport, adoption or startup was attempted. This read-only
run predates build 05's final error-path/tests changes; it is not a build 05 live
startup result. See `artifacts/compatibility-20261105-01`.

Still required before a new protocol release: build an image with the explicit
pairing declaration, import into a newly owned test instance, initialize locally,
verify first frame/input/display and complete normal stop/restart and relevant
VM-exit acceptance. No new image has been built, imported, published or promoted
in this step. The existing CachyOS session was not stopped or changed. Other
researched desktops are design coverage only; no source adapter or hardware
support is implied.
