# ADR 003: Distro-addressed desktop control and observed state

Status: accepted direction; bounded first implementation, 2026-11-05.

## Decision

Daily desktop operations use `-d DISTRO desktop ...`. WSL registration is the
authority for distro identity/existence, Guest queries for account/session facts,
and the corresponding native runtime for live graphics ownership. The public
EXE remains a short-lived caller of its embedded Core. No business daemon,
private-repository dependency or replacement graphics protocol is introduced.

Observation must not require the Core installation index, active desktop pointer
or historical startup phase. Discover live processes and validate their actual
entry arguments, executable hash/profile, creation time and registration binding.
Keep uncertain identity explicit. A missing process is never retirement proof.

Mutation is serialized by actual registration GUID. New native lifetimes bind
that GUID and disk to their runtime configuration, preventing same-name reimports
from inheriting a previously bound lifetime. Legacy unbound Hosts are observable
but are not adopted by the new stop entry. Installation ownership and interrupted
device-operation journals remain necessary for the existing candidate startup.

## Alternatives and limits

Deleting all Windows records now would lose installation provenance and partial
operation recovery. A running flag in JSON would merely duplicate runtime state.
Neither is used as the new status authority. Query transcripts remain diagnostic
artifacts, not a second live-state database.

The pinned Host does not implement a live health/retirement query. Windows process
and stop-event observations are available, while quarantine diagnosis still uses
legacy logs and explicitly advertises that limitation. A paired component update
must provide direct lifecycle results before removing legacy recovery receipts.
Reference graphics/prototype repositories remain read-only in this implementation.

Guest queries skip known stopped distros and recheck liveness before execution.
There is still a race with external termination because `wsl --exec` may start a
distro after the check. Atomic existing-session-only observation remains open.
Concurrent desktop startup remains blocked by the shared-resource admission rules.
Neither arbitrary imported distros nor old machine-local runtime packages are
automatically adopted.

## Evidence

`distro-desktop-build-20261105-04` passed 33 native Rust tests. Sixteen Python tests
passed. `distro-desktop-acceptance-20261105-01` passed ten Windows command/adapter
cases: status with a corrupt private Core index, stopped-distro observation,
refused mutation with an unresolved existing Host, unknown input rejection, and
an inert process exercising exact stop-event identity plus wrong-registration
and process-creation-time refusal. Existing native process identities and the
running distro set remained unchanged.

This machine has no Core-owned r10 test import and has an unrelated legacy Host.
No real desktop was started or stopped. The positive stop test uses an inert
event fixture, not GPU/HDV retirement. Full distro-addressed GPU start/stop/restart
and abnormal recovery remain pending.

## Default launch follow-up, 2026-11-05

`-d NAME` and `--distribution NAME` now default to the same desktop-start path.
An explicit runtime override remains available, while the default uses one
hash-pinned versioned cache directory. This is component configuration, not a
persisted running-state authority. Account initialization delegates to Guest ABI
1 with local non-echoed password prompts; observed account/UID data remains Guest
owned. The r11 import receipt is bound to the actual WSL registration GUID and
archive digest. r10's successful native/device/session implementation is reused.

The old 64 MiB live Host observation ceiling incorrectly excluded the admitted
68,677,120-byte reference binary. Observation now checks its exact known size
and the existing SHA-256. This does not admit other Host versions or ownership.
A running unrelated service-style Host still blocks direct startup; no coexistence,
service restart or automatic environment migration policy was added.

## Paired close follow-up

ADR-004 records the new paired Host/renderer and real r11 close retirement. Live
process discovery accepts either of the two exact known Native hashes; startup
requires the new complete pair. Current status still does not infer retirement
from absence or read the startup pointer. Historical machine/acceptance statements
above describe the earlier test sessions and are not current running-state facts.
