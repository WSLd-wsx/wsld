# ADR 005: External distro and original-VM retirement

> Historical experiment paths referenced below were moved to the prototype repository; see [Experiment migration](EXPERIMENT-MIGRATION.md).

Status: historical implementation; distro termination accepted and real VM-shutdown retirement failed on 2026-11-05. See [ADR 006](ADR-006.md) for the subsequent repair and its bounded verification.

## Decision

`wsl --terminate NAME` and `wsl --shutdown` are different authority transitions.
Stopping the distro does not prove the shared kernel/device has retired. Original
VM exit closes Guest admission but does not prove Windows GPU/memory reclamation.
The Native graphics Owner handles both transitions while public Core remains a
short-lived caller. WSL registration, Guest and Native observations remain the
state authorities. No persistent business service or additional instance database
is introduced.

Native asynchronously polls the exact distro name in WSL's running list. Once a
previously observed running distro disappears, it signals its pre-existing system
helper to perform the exact PCI instance's synchronous kernel retirement. The
helper is launched and handshakes before desktop rendering, then waits on stdin;
it is not launched in reaction to distro/VM loss. The stopped user distro stays
stopped, and VM shutdown cannot trigger a new system helper invocation. Unused
helpers exit on EOF and are observed before final Native success.

The helper uses WSL's system distribution, not another user-installed distro.
It requires root and standard shell/sysfs tools, checks exact VMBus ancestry and
WSX driver identity, and writes only that device's existing retire attribute.
The original queue continues servicing UNREF/RESET and draining GPU work. No
kernel module or graphics protocol is changed. System-environment unavailability
fails readiness; the product does not install tools or silently fall back.

The retained HCS handle of the original VM supplies a separate exit observation.
A successful `HcsWaitForComputeSystemExit` can replace the Guest-users barrier and
the HCS Remove request, never GPU/context/completion drain, memory lease closure,
HDV teardown or callback rundown. A bounded stream-error reconciliation checks
that same handle before attempting closure. Unknown HCS/HDV failures retain state.
No new VM discovered by name is adopted. Core accepts the exact VM-exit marker
only together with zero retained memory, final native closure and process exit;
known quarantine still overrides all apparent success markers.

## Evidence and limits

The first implementation passed real r11 external termination in
`artifacts/external-termination-live-20261105-01`. Native instance
`aafe357b-e425-4d10-a64b-d2986be13957` (PID 19384) displayed the desktop, observed
r11 stop, retired the exact device through the system environment, reached zero
retained memory, and exited with the input process, both code zero. Core separately
confirmed `native_retired`. The target stayed stopped, Ubuntu-24.04 kept running,
and all nine WSL registration identities were unchanged. No Host was killed.

That first build spawned its system helper after observing distro stop. The
current follow-up pre-binds the helper to avoid the VM-shutdown/start race;
its separate acceptance is recorded below rather than inheriting the first result.

Windows fixture evidence in `artifacts/external-lifetime-fixtures-20261105-01`
covers actual C code with simulated HCS timeout/error/exit returns and two Rust
UTF-8/UTF-16 parsing tests. It does not stop a real VM or execute GPU work.
Core tests additionally require complete retirement after exact-instance HCS exit;
process absence and partial drain remain insufficient.

The initial acceptance used distro termination because Codex runs in another
distro. The user subsequently authorized one real VM shutdown and manually
restored this conversation; that failed result is recorded below. VM-loss HDV
retirement, repeated/stress close/terminate races, hardware loss and a fresh
Iris Xe run are not accepted. The first and follow-up real distro tests are
on NVIDIA GeForce RTX 3080 Ti, selected by active display/LUID without a vendor
branch. Normal-close/external-stop concurrency retains the legacy normal-close
`wsl --exec` check/start race; the external-loss path uses the pre-existing helper.
A failed cleanup is retained and reported; there is no forced-cleanup fallback.

Microsoft's [WSL command reference](https://learn.microsoft.com/en-us/windows/wsl/basic-commands)
describes the distinct distro/VM operations. [HCS exit wait](https://learn.microsoft.com/en-us/virtualization/api/hcs/reference/hcswaitforcomputesystemexit)
and [HDV teardown](https://learn.microsoft.com/en-us/virtualization/api/hcs/reference/hdv/hdvteardowndevicehost)
are separate API contracts, not evidence of a successful real shutdown test.

## Real VM shutdown acceptance: failed

Evidence: `artifacts/shutdown-acceptance-20261105-01`, copied from the Windows-local
collector with all 50 files verified by SHA-256 in `archive-manifest.json`.
The independent Windows collector survived the authorized shutdown; the user
restored Ubuntu/Codex manually. No second shutdown or forced cleanup was performed.
This test used the final public package and graphics pair listed above.

Run `2e542177-3626-4578-bf06-7264812bd4fe` executed `wsl.exe --shutdown` once.
The command exited 0 at 2026-11-05T06:43:56.5565546Z. Original VM
`c3980879-f6cc-49b3-8f30-350fc77099ac` exited, confirmed by its retained HCS
handle and separate enumeration. All nine registration identities were preserved.
Native instance `c3c7395e-2bc3-4faf-9a4c-e27cc0706b3b` (PID 18984) entered drain
but failed Guest RAM lease closure with `Native(-2147024890)` (`0x80070006`).
The failure snapshot retained 218 slots, 217 usable pages / 888832 bytes, and one
slot without a Rust view. Neither zero retained memory nor final native closure
was observed. Input exited normally with code 0; the pre-existing system helper
exited with code 1. Native remained quarantined on its original COM thread.
Core independently reported `failed_retained`, `native_retirement_confirmed=false`
and `restart_requires_retirement=true`. The bounded collector completed with
`passed=false` at 06:45:57Z. Original VM exit is not sufficient recovery evidence.

The log also records a normal Guest retirement command failing to find the old
PCI instance. Immediate post-command enumeration already found a different VM
in Created state, later Running. The collector itself issued no automatic restart;
that flag is not proof that the product never raced a new WSL invocation. Existing
normal-close `wsl --exec` admission can race shutdown. The exact source of the new
VM is not established by these records. Final running-list evidence contains only
Ubuntu-24.04. Preserve this race as unresolved rather than attributing it to the user.

Required follow-up: diagnose the VM-loss lease-close failure at the native API
boundary, establish a valid reclamation contract without treating invalid handles
as successful GPU cleanup, and remove the normal Guest invocation/shutdown race.
The current test did not change native cleanup code or establish safe recovery for
this quarantined Host. Do not kill it, reload modules or repeat shutdown to turn
this failed acceptance into a pass. Raw logs, screenshot, process/VM identities,
registration snapshots and Core readback remain archived.
