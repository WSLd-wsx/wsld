# ADR 016: Product graphics routes and Guest bootstrap v2

Status: accepted product implementation; hardware and release validation remain
specific to the tested builds and environments.

The launcher selects one independently catalogued Linaro-based Native Host and
renderer per Owner lifetime. It prefers opaque zero-copy and may select staging
when opaque is unsupported, staging capabilities and the installed Guest are
admitted, and the machine-wide startup gate permits the route. A live Owner
does not change routes. Failed retirement retains resources and prevents unsafe
reuse. Guest bootstrap v2 pins the verified adapter to its session; Guest image
graphics remain in the image-owned runtime.

Omarchy r17 was imported and initialized using wsld. Its v2 desktop was observed
with zero-copy and the user confirmed display and input; Guest, input, mapping
and Native retirement were recorded. A diagnostic MSVC build simulated an
unsupported opaque result while preserving actual staging capability, package,
Guest and kernel admission. On the same machine the independently paired
staging Host presented the r17 desktop and the user confirmed the title, display
and input. The recorded actual opaque observation was supported. This exercise
does not prove automatic fallback on hardware that actually lacks opaque support,
nor does it independently establish staging retirement for this build.

`simulate-opaque-unavailable` is a compile-time acceptance feature, disabled in
normal builds. It must never be distributed as a product build. Its evidence
explicitly records the simulated observation and the actual opaque result.
