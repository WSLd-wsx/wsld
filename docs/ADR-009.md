# ADR 009: Fresh startup follows current runtime authorities

The user requires a stateless Windows command model: WSL, Guest and the actual
Native Host own running state. A historical failure journal must not indefinitely
lock a new desktop. This supersedes ADR 007's requirement for an old Host log's
original-HCS exit marker as a prerequisite for admission to a different VM.

Current successful HCS discovery must exclude the original VM and identify a
different valid current VM. The old Native process identity must have ended, and
no graphics Owner may remain. Those observations permit only fresh admission:
Guest preflight must still reject loaded modules, retained descriptors, seat
owners and incompatible components. Recheck the same current VM before starting
the new device. Do not reuse backing or unload modules through this route.

The old diagnostic lifecycle stays failed and normal retirement stays false.
No manually written recovery receipt or edited state flag is required. Current
observation failures, live Owners, an unchanged VM or dirty Guest still reject.
This is not automatic permission to kill an Owner or restart a service.

The existing startup path still reads the previous lifetime's provenance and
registration binding to distinguish fresh admission from same-VM module reuse.
This change removes the historical log gate; it does not claim all historical
startup files or installation ownership journals have been eliminated. Daily
status already discovers the actual Host without using the active pointer.
