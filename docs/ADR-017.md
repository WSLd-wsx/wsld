# ADR 017: Community and Store GUI editions

Status: integration slices build; the currently shipped GUI still uses the
validated Tauri DLL. This record does not admit a new Store package.

Build a community edition from the public wsld repository alone. Build the Store
edition from the private wsx-pro repository using the same public frontend and
Core. Each edition builds one PE copied unchanged to wsld.exe, wsx.exe and
wsxdesk.exe; the editions need not have identical binaries. The intended final
GUI integration is an in-process Rust crate, not a Pro DLL. Explicitly measure
static and runtime imports, WebView2, CLI piping, exit codes, Ctrl+C and Explorer
launch behavior before replacing the existing loader.

The public `gui` crate exposes the edition interface and the community backend.
It allows inventory and terminal access but rejects GUI desktop launch. The
private Store backend checks Microsoft Store entitlement at each paid action and
the Store integration slice uses the existing purchase and license integration.
A UI visibility flag, test provider or Store installation is not proof of
purchase. No background service or second business Core is introduced.

The shared frontend resides in `gui/ui`; its existing distro-specific command
quoting and free/Pro presentation are retained. The existing Tauri DLL and the
new in-process community and Store slices consume it. The community slice was
observed with a real distro list, terminal and command prompt. Both slices built
on Windows MSVC, dispatched using the real executable path despite forged argv[0],
and rejected an unknown executable name. Their CLI version, full
pipeline and invalid-argument exit paths passed. A sampled community CLI process
loaded Windows GUI system libraries; no Pro DLL or WebView2 module was observed.
One sample does not establish all CLI, Ctrl+C, Explorer or Store package behavior.
An early-closing PowerShell pipeline produced inconsistent exit results in both
new builds; the earlier DLL baseline also returned `-1` in the same check. The
underlying pipeline behavior needs investigation. Building the slices does not complete product or MSIX
acceptance, nor does unpackaged Store execution prove purchase entitlement.

The intended wsld release license is BSL 1.1; existing repository license files
remain unchanged during this code transition. Private Store source is not copied
into the public repository. Preserve all upstream licenses and record the actual
release terms before distribution.
